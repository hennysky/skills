# 汇报场景骨架

按场景选骨架，不要所有汇报用同一个模板。每类给了适用场景、页数、骨架和特别注意点。

---

## 通用规则

- 所有骨架都遵守 `内容规范.md` 的三条铁律和颗粒度要求
- 页数只是建议，内容不够宁少勿凑
- 骨架顺序可以按实际调整，但**结论永远靠前**

---

## 1. 双周汇报（最常用）

**适用**：固定周期向直接上级汇报进展。两周一次，节奏快。

**页数**：6～8 页

**骨架**：

```
1. 本期概览           —— 3 个数字化指标，一眼看懂本期做了什么
2. 已完成              —— 按项目分组，每组 2～3 条，带数字
3. 进行中              —— 进度百分比 + 卡在哪一环
4. 现状与方向          —— 原「问题」部分，用现状/方向/价值三段式
5. 下期计划            —— 3～5 项，每项有可验证的完成标志
6. 需要支持            —— 只写需要什么，不写谁该给
```

**特别注意**：

- 双周节奏快，**不要回顾上期已完成的东西**，只讲本期的增量
- 「进行中」必须写清卡在哪一环，不要只写「推进中」
- 「需要支持」最多 2 条。写多了显得能力不足
- 整个汇报控制在 10 分钟能讲完的信息量

---

## 2. 月度总结

**适用**：月末向部门或上级汇总整月工作。

**页数**：8～12 页

**骨架**：

```
1. 月度关键数据       —— 4 个大数字，横向对比上月
2. 目标完成情况       —— 目标值 vs 实际值 vs 完成率，表格呈现
3. 重点工作回顾       —— 3～4 项，每项讲「做了什么 → 结果是什么」
4. 差距与原因         —— 差距要具体，原因要对应得上
5. 下月目标           —— 目标值 + 关键动作 + 里程碑
6. 需要的资源         —— 人、钱、权限，分开写
```

**特别注意**：

- 目标完成情况一定要用**表格**，三列：目标 / 实际 / 完成率。这是最容易看懂的形式
- 「差距与原因」如果完成率超过 100%，差距改成「未达预期的部分」或「结构性短板」，不要硬编问题
- 数字化目标（如提效多少小时）比过程描述更有力

---

## 3. 专项汇报

**适用**：单一主题深入汇报，比如某个项目立项、某个方案评审、某次故障复盘。

**页数**：6～10 页（看复杂度）

**骨架**：

```
1. 一句话结论         —— 开头就把结论放出来
2. 背景与现状         —— 为什么现在要讲这件事，带数据
3. 方案 / 分析        —— 核心内容，可用对比表格或分步说明
4. 依据与验证         —— 为什么这个方案成立，数据和测试结果
5. 风险与应对         —— 主动列出风险，每条配应对措施
6. 需要的决策         —— 明确要对方拍板什么
```

**特别注意**：

- 「一句话结论」必须在第一屏。领导只看一页也能知道你要什么
- 「风险与应对」一定要写。主动列风险的方案显得成熟，不列反而会被追问
- 「需要的决策」要具体到「批准 / 不批准 / 选 A 还是 B」，不要写「请领导指导」

---

## 4. 转正述职 / 晋升答辩

**适用**：试用期转正、晋升评审、岗位竞聘。

**页数**：10～15 页

**骨架**：

```
1. 个人定位           —— 我是谁，负责什么，一句话说清
2. 核心成果           —— 3～4 项，每项：背景 → 我做了什么 → 量化结果
3. 能力证明           —— 挑 1～2 项展开，讲清难度和判断过程
4. 不足与改进         —— 1～2 条，必须配具体改进动作
5. 未来规划           —— 分阶段，每阶段有目标和可验证的产出
6. 需要的支持         —— 资源、权限、协作
```

**特别注意**：

- 「核心成果」是全场最重的部分，占一半篇幅。每项必须有**可核对的数字**
- 「不足」不能写假不足（如「太追求完美」）。写真实但可控的，并且后面紧跟改进动作
- 「未来规划」要贴合岗位，不要写空泛的行业展望
- 提前想好会被追问的点：数字怎么来的、为什么是你做的、遇到最大困难是什么

---

## 5. 年度复盘

**适用**：年终总结、年度规划会。

**页数**：12～18 页

**骨架**：

```
1. 年度全景           —— 全年核心数字，4～6 个大数
2. 目标达成           —— 年初目标 vs 年终实际，逐项对账
3. 关键战役           —— 3～5 件大事，每件讲清「难在哪 → 怎么破 → 结果」
4. 能力沉淀           —— 沉淀了什么方法、工具、机制
5. 未完成与反思       —— 哪些没做到，为什么，学到什么
6. 明年规划           —— 目标 + 重点方向 + 关键里程碑
7. 需要的支持
```

**特别注意**：

- 「年度全景」的数字要能覆盖全年，不能只挑好的月份
- 「能力沉淀」是最容易被忽略但最加分的部分——说明你不只是干活，还在留下东西
- 「未完成与反思」要有真反思，不能全是客观原因
- 明年规划的目标值要能推演出过程，不要拍脑袋

---

## 6. 申请与说明类（报销 / 资源申请 / 立项审批）

**适用**：报销申请、服务器/软件/预算申请、工具采购、立项审批。凡是「要别人批」的都算。

**页数**：5～8 页（报销常 1 页也够）

**骨架**：

```
1. 一句话申请         —— 申请什么 + 金额 + 用在什么地方
2. 现状               —— 现在是什么状态，带具体数字（内存 4GB、负载 85%、月均超时 3 次）
3. 不解决的后果       —— 具体会发生什么，要能说出场景不要讲道理
4. 方案               —— 打算怎么解决，为什么是这个方案
5. 效果               —— 解决后的对比数据，能给出「改前 vs 改后」最好
6. 金额构成           —— 明细表格：项目 / 单价 / 数量 / 小计 / 合计
7. 附件清单           —— 发票、合同、报价单、截图，一一列出
```

**核心原则：不要一上来要钱，先证明「不解决会出事」。**

这是这类汇报与述职的根本区别：

| | 述职 / 总结 | 申请 / 报销 |
|---|---|---|
| 目的 | 证明我干得好 | 证明这件事必须做 |
| 逻辑 | 我做了什么 → 结果 | 现在有问题 → 不解决会怎样 → 所以要做 |
| 情绪落点 | 认可 | 紧迫感 |

**「不解决的后果」怎么写**：

- ❌ 讲道理：「资源不足会影响业务发展」
- ✅ 说场景：「四类工作挤在 4GB 里，任何一项跑满，其余三项一起卡住；上个月出现过 2 次查数据卡死，需要重启」
- 有发生过的具体事件就用，没有就说清「会发生什么」，但必须具体到场景

**「效果」怎么写**：最好给「改前 vs 改后」的对比数字。没有实测数据时，说明这是预期并给出推算依据。**不要编数字**——报销单上的数字是会被核对的。

**特别注意**：

- 金额构成必须是表格，逐项列清。含糊的总额最容易被退回
- 附件清单要写全。报销被退回，一半原因是缺附件
- 不要写「恳请领导批准」这类话。把必要性证明清楚，批准是自然结果
- 多格式输出是加分项：HTML 用来快速看，PDF/DOCX 用来走流程归档

---

## 骨架选择速查

| 场景 | 页数 | 核心页 | 最容易搞砸的地方 |
|---|---|---|---|
| 双周汇报 | 6～8 | 已完成 / 现状与方向 | 回顾太多，本期增量太少 |
| 月度总结 | 8～12 | 目标完成情况 | 差距和原因对不上 |
| 专项汇报 | 6～10 | 一句话结论 | 结论藏在最后 |
| 转正述职 | 10～15 | 核心成果 | 数字不可核对 |
| 年度复盘 | 12～18 | 关键战役 | 只讲成绩不讲反思 |
| 申请 / 报销 | 5～8 | 不解决的后果 | 一上来就要钱，没有必要性证明 |
