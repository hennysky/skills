# 计划内容与格式

完整计划以读者能执行为目标。章节可依实际需求调整，不能用摘要替代实施细节。网页与 DSH Markdown 由同一源生成。

建议正文覆盖：

| 内容 | 要求 |
| --- | --- |
| 目标与范围 | 本轮解决什么、哪些项目或用户受影响、明确排除项 |
| 现状依据 | 实际文件/接口、已观察行为、证据日期；假设和待确认信息单列 |
| 关键决策 | 选择、原因、限制及兼容边界 |
| 文件或模块 | 真实存在路径与拟新增路径明确区分 |
| 接口与数据 | 输入/输出、错误、权限、持久化、兼容和幂等按相关性填写 |
| 按依赖实施 | 步骤 ID、前置、动作、产出、验证、失败处置；不要凭空指定负责人或日期 |
| 测试与验收 | 可实际执行的命令和预期；自动检查、人工业务验收、生产验证分别记录 |
| 风险与回滚 | 触发条件、退回对象、保留数据、权限与上线边界 |
| 待办 | `- [ ] T1 具体动作`；已核实完成才用 `- [x]`，规划任务默认不勾选 |

格式：第一行 `# 标题`，第一段直接说明方案结论。后续用平级 `## 章节`；支持平级列表、任务列表、表格、代码块、粗体和行内代码。使用 `##` 分阶段可保留完整长计划。不要用原始 HTML、嵌套列表或三级标题；当前页面解析器会拒绝它们。复杂内容改为表格或独立二级章节，不能删减。

图形：流程、系统组成、往返调用、数据流、状态、关系模型等应选择对应原生类型。跨项目方案可用两张图，第二张可在计划源稿中使用内联原生指令；同页最多四张图。主要图使用构建脚本 `--diagram` 参数。额外 JSON、CSV 或图片资产需采用原生整页制作流程并将资产放在交付目录；当前计划构建器只自动复制主要图。

清单按页面修订隔离保存。勾选仅表示读者本机进度。更新状态的依据、实际执行证据及后续反馈写回计划源或项目原有任务系统，再重新生成；不得从勾选推断业务成功。

修订命名使用可辨认主题及时间或修订号。导出目录中保留 `DSH-实施计划.md`、图规格、页面源稿、内容指纹和收据；网页能离线打开，图可在页内展开。不要在公开交付中嵌入凭证、真实客户数据或项目无权公开的信息。

页面默认采用 `layout=planning` 的方案阅读版式，独立于通用说明的自动拼卡布局。章节数量、图数量、待办总数从真实内容计算；不虚构完成率或项目状态。目录在桌面侧栏随滚动标记当前位置，窄屏可展开/收起；完整正文始终保留。样式与主题可切换，规划页样式偏好与通用说明页分别保存。
