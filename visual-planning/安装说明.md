# 可视化规划 · 安装说明

> 适用对象：拿到 `visual-planning-1.1.0.zip` 的同事
> 全程约 5 分钟，只需要在终端里粘贴三条命令

---

## 这是什么

一个能帮你把「方案、计划、流程」变成**可点击交互网页**的工具。

你把想法说给 AI，它帮你出一份网页：左边有目录、中间有可展开的流程图/架构图、正文完整，还能勾选待办进度。
适合：写方案、做实施计划、给领导汇报技术方案、跨部门交接。

---

## 装之前，先确认一件事

需要电脑上装了 **Node.js**（版本 18 或以上）。这是唯一的前提。

打开「终端」（Terminal），粘贴这一行，回车：

```bash
node -v
```

- 显示 `v18.x.x` 或更高（比如 `v20.11.0`、`v22.22.2`）→ 可以继续
- 显示 `command not found` → 先去 https://nodejs.org 下载安装 LTS 版本，装完重开终端再试

---

## 安装：三步

### 第一步：解压到技能目录

把 `visual-planning-1.1.0.zip` 解压后，会得到一个叫 `visual-planning` 的文件夹。
把它整个挪到下面这个位置（如果 `skills` 文件夹不存在，就自己新建一个）：

```
~/.workbuddy/skills/visual-planning
```

用命令做就是（假设 zip 在「下载」目录）：

```bash
mkdir -p ~/.workbuddy/skills
unzip -q ~/Downloads/visual-planning-1.1.0.zip -d ~/.workbuddy/skills
```

> 别改文件夹名字。`skills` 下面的文件夹名要和包里的一致，AI 才能认出来。

### 第二步：自检

```bash
cd ~/.workbuddy/skills/visual-planning && node bin/visualplan.mjs doctor
```

看到一排 `[ok]` 就是装好了。最后会显示类似：

```
[ok] Node.js v22.22.2 (requires >=18)
[ok] Core template
[ok] architecture renderer, schema, and example
...
[ok] Explainer runtime and reader assets
```

**只要有一条 `[fail]`，就是没装好**，把报错内容发给技能提供者。

### 第三步：重启 WorkBuddy

关掉 WorkBuddy 再打开，让它重新扫描技能目录。

## 怎么用

直接对 AI 说人话就行，比如：

- 「用可视化规划，把我的推广费汇总方案做成一个规划页」
- 「画一张我们部门的数据流转架构图」
- 「把这个项目的实施步骤做成带待办清单的网页」

也可以叫它的英文名 `$visual-planning`。

**AI 会做什么：** 先读你的材料 → 写一份完整的实施计划 → 按内容选图（架构/流程/时序/数据流等 10 种）→ 生成一个独立网页 + 一份 Markdown。

生成的网页可以直接双击打开，也能发给别人看（不需要对方装任何东西）。

## 常见问题

**Q：自检时 `browser-check` 报错，说找不到 Chrome？**
不影响使用。这只是「自动检查页面显示是否正常」的环节，你的电脑上有 Chrome 就能过；没有的话页面照样能生成，只是少了这一步自动验证。

**Q：在 WorkBuddy 或 Codex 里让它生成，报 `removal-quarantine-cleanup-failed`？**
不是包坏了，是宿主软件的文件保护钩子拦了它清理临时文件。解决办法：让 AI 在命令前加 `env -u NODE_OPTIONS`，例如：

```bash
env -u NODE_OPTIONS node bin/visualplan.mjs finalize tree spec.json out.html --quality showcase --out-dir <新目录>
```

其实这时候页面已经生成好了，去目录里看看有没有 `.html` 文件，有就能直接用。

**Q：AI 说找不到这个技能？**
检查两件事：① 文件夹路径是不是正好 `~/.workbuddy/skills/visual-planning`；② 这个文件夹里有没有 `SKILL.md` 这个文件。改完重启 WorkBuddy。

**Q：生成的图太挤 / 字太小？**
跟 AI 说「按密集模式重新生成」，或者「这张图拆成两张」。这个工具更擅长画主流程，塞太多细节反而看不清。

**Q：我能改它的代码吗？**
可以。它是 MIT 协议开源的，随便改、随便传，只要能保留 `LICENSE` 和 `THIRD_PARTY_NOTICES.md` 就行。

**Q：占了多大空间？**
约 20MB，不需要联网、不需要装依赖包。

## 包里的东西都是干啥的（不用全懂）

| 位置 | 是什么 |
|---|---|
| `SKILL.md` | 主文件。AI 靠读它来决定怎么干活 |
| `bin/visualplan.mjs` | 主程序入口，画图和检查都从这进 |
| `scripts/planning-page.mjs` | 生成「规划页」的构建器 |
| `renderers/` | 10 种图各自的渲染器 |
| `schemas/` | 每种图的格式规范（写错了会被拦下） |
| `examples/` | 每种图的示例，可以照着改 |
| `assets/` | 离线字体、模板，保证断网也能用 |
| `docs/VERIFICATION.md` | 验收记录：做过哪些检查、结论是什么 |
| `licenses/` | 来源声明和许可原文（合规用，别删） |
